Added MSSQL-specific trace attributes:
- `MssqlServer` - SQL Server instance  
- `MssqlDatabase` - Database name

## How It Works

All SQL Server queries are **automatically traced**:

```
HTTP Request
  └─ EF DbContext Operations  
	  └─ SqlClient Query Execution ← Traced here!
		 - Query text
		 - Database name  
		 - Execution time
		 - Success/failure
```

🎯 **What Gets Traced**
- All `SqlCommand` executions

## Usage

### Development (Console Output)
```json
{
  "OpenTelemetry": {
	"Enabled": true,
	"ConsoleExporter": true,      // Shows traces in output
	"OtlpEndpoint": "...",
	"SamplingRatio": 1.0          // 100% of traces
  }
}
```

Example console output:
```
Activity.DisplayName: sql
Tags:
  db.system: mssql
  db.name: YourDatabase
  db.statement: SELECT * FROM Users WHERE Id = @p0
  db.user: domain\username
  db.mssql.duration_ms: 12.5
```

### Production (OTLP Collector)
```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=http://jaeger:4317
# or
export OTEL_EXPORTER_OTLP_ENDPOINT=http://tempo:4317
```

Then view in:
- **Jaeger**: http://localhost:16686
- **Grafana Tempo**: Integrated with Loki
- **Datadog**: APM > Traces
- **Azure App Insights**: Application Insights

## Troubleshooting

**No SQL traces appearing?**
- ✓ Check: `OpenTelemetry:Enabled` = true
- ✓ Check: Database queries actually executing
- ✓ Check: `ConsoleExporter` = true (in development)
- See: `MSSQL_INSTRUMENTATION.md`

**Sensitive data concerns?**
- ✓ Use parameterized queries (automatic with SqlCommand)
- ✓ Connection strings already hidden
- ✓ Configure OTLP backend to mask PII
- See: `MSSQL_INSTRUMENTATION.md` → Troubleshooting

**Performance issues?**
- ✓ Reduce `SamplingRatio` (e.g., 0.01 for 1%)
- ✓ Disable `RecordException` if not needed
- See: `ARCHITECTURE.md` → Performance Characteristics
